# Security

LifeLink India has two parts: a static guide to official blood-service resources and a phone-verified community contact-matching service. The matching service uses a Cloudflare Worker and D1, with Firebase Authentication for phone OTP. It is not a hospital, blood bank, donor eligibility check, or clinical compatibility service.

## Report a security issue

Email [abhinash1023@gmail.com](mailto:abhinash1023@gmail.com) with the affected page and steps to reproduce. Do not include patient records, donor numbers, OTPs, passwords, or other sensitive information. There is no formal bug-bounty program or guaranteed response time.

## Hosting and configuration

The matching service requires the Cloudflare Worker and D1 migration in this repository. The existing GitHub Pages site cannot run the API and must not be treated as a working matching service. Do not merge and publish the matching page to GitHub Pages alone. Configure Firebase Authentication, the Worker variables, D1 binding, and encryption secret before exposing matching to visitors.

The Cloudflare `_headers` file applies to static asset responses on Workers hosting. It does not configure GitHub Pages response headers, and it does not apply to responses generated by Worker code. API responses set their own headers.

## Security boundaries

- Firebase phone OTP proves access to a phone number only. It does not verify identity or donor eligibility.
- A request phone is encrypted with AES-GCM before storage; the Worker holds the key so it can reveal the number after consent.
- Only an exact recorded blood-group and district match can view an active request or request a contact reveal. This filter does not establish medical compatibility.
- Requesters opt in before their verified number can be released. A recipient may retain or forward a number after seeing it.
- No system can guarantee security; monitor Firebase SMS quotas and Cloudflare usage, protect the encryption secret, and remove access promptly if it is exposed.
